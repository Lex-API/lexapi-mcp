# Changelog

All notable changes to `@lexapi/mcp`. Versions follow [semver](https://semver.org); while the package is 0.x, a minor bump can change behaviour.

## 0.5.2 — unreleased

### Added
- **`lex_check_citation`** (read-only): looks a citation up. Takes a CELEX, EUR-Lex URL, ELI or ECLI, or a national document id, and optionally an article and a date. Returns whether the document exists, its canonical id, title and link, whether the article is in its text, whether the act is in force today, and the latest consolidated version when the API reports one. `exists`, `inForce` and `article.found` are `"unknown"` when the check could not be made (not a statement that the document or article does not exist); `notChecked` lists what could not be checked and why. `exists` is `true` only for an answer that carries the requested document and `false` only on the API's `NOT_FOUND`. Article forms such as "Art. 17(1)" are read as the article number (the paragraph or point is not checked); the article is compared with the text's article units and is `"unknown"` for a text without them. Cost: 1 credit to resolve a URL, ELI or ECLI, plus one metadata or document read (1 / 4 / 5), plus a second document read when an article is not matched; a national id costs 1.
- **`lex_act_history`** (read-only): the acts that amend, correct or repeal an EU act (`lex_cited_by` relations of those three types), with the act's title, dates, in-force status and end of validity. `since` filters by the year of each CELEX number, and by document date for the entries read with `dates` (up to 10). A relation carries no date, and consolidated versions are shown only when the API reports them. Every result says that the relations may be incomplete; an act the API reports as not found returns `exists: false` and no changes. Cost: 1 credit per page of relations, plus the act's metadata (1 / 4 / 5), plus the same for each date read.
- **`lex_research`** (read-only): one query run as semantic searches over EU legislation, EU case law and the legislation and case law of chosen live countries (at most 8 jurisdictions), merged into one list. `sources` reports every search as `ok`, `failed` or `not_run`, with the reason. No further search starts once credits or the rate limit run out. A plan refusal, an exhausted national allowance or unaccepted national terms stop the remaining national searches. Cost: 5 credits per search run.
- **`lex_legislation_as_of`** (read-only, scope `lex:read`): for a known EU regulation, directive or decision and a date, the version the Publications Office lists for that date (the newest consolidated version dated on or before it, else the act as published in the Official Journal) and, with `provision`, the text of one article, annex or recitals in it. Parameters: `document` (CELEX; a consolidated CELEX is read as its base act), `asOf` (required, `YYYY-MM-DD`), `provision` and `language` (both optional); any other parameter is a validation error. The version and text are established only when `asOfResolved` is `true`; otherwise the result carries `asOfResolved: false`, `asOfReason` and an `asOfCaveat` (the reason's class and meaning), and never a text. It does not say whether an individual provision applied on the date; a retroactive amendment counts from the date of the amending act; consolidated versions have no legal force. A provision text longer than 40,000 characters is cut, with a note. Cost: 1 credit when no text is fetched; when the provision's text is fetched, 4 via the Publications Office or 5 live, whatever the answer (1 if the fetch fails or finds no text). Requires LexAPI API 2.26.0: on an older API the tool returns an error saying that the deployment does not offer the endpoint yet.
- **OAuth scopes** on the hosted server: `lex:read` (every tool except the webhook tools), `lex:webhooks` (the six webhook tools, `lex_list_webhooks` and `lex_get_webhook` included) and `lex`, which stands for both. Each tool declares the scope the API requires for the routes it calls. A connection is offered only the tools of its scopes in `tools/list`; a `tools/call` for a tool outside them is answered `403` with `WWW-Authenticate: Bearer … error="insufficient_scope"` and the scope to request (the scopes the connection holds plus the ones the call needs), before any request is made to the API. A `403 insufficient_scope` from the API is passed on the same way (as a tool error once the response has started). Scope names the server does not know are ignored; a token without a known scope is refused with `401 invalid_token`, as before. A connection that does not hold both scopes gets one more sentence in the server instructions, saying that some features are not enabled on it. Tokens with scope `lex` see and call every tool, as before. API keys are not subject to scopes, on stdio and on the hosted server.
- Hosted server configuration: `LEXAPI_OAUTH_SCOPES` (default `lex`) lists the scopes the authorization server accepts, published as `scopes_supported` and used for the `scope` of an `insufficient_scope` challenge; `LEXAPI_OAUTH_DEFAULT_SCOPE` (default `lex`) is the `scope` of the `401` challenge. With the defaults the metadata document and the `401` challenge are unchanged. Set `LEXAPI_OAUTH_SCOPES` or `LEXAPI_OAUTH_DEFAULT_SCOPE` to the narrow names only after the authorization server accepts them; until then leave both unset. The server refuses to start when either variable names an unknown scope or lists no scope name, when `LEXAPI_OAUTH_SCOPES` does not cover every tool (it must list `lex`, or both `lex:read` and `lex:webhooks`), when `LEXAPI_OAUTH_DEFAULT_SCOPE` names a scope that `LEXAPI_OAUTH_SCOPES` does not list or includes neither `lex` nor `lex:read`, and when either is set without `LEXAPI_OAUTH_CLIENT_SECRET`.
- Every API request carries an `X-LexAPI-Client` header: `lexapi-mcp/<version>`, `mode=hosted` (HTTP entry) or `mode=stdio` (stdio entry), `tool=<tool name>` while a tool is executed (a workflow tool's name on each call it makes) and, in stdio mode, `app=<name>[/<version>]` from the MCP client's `clientInfo`, reduced to letters, digits, spaces and `._()+-`. The hosted server does not send the connecting client's name. The `User-Agent` is unchanged.
- The in-force label of LexAPI API 2.19.0 (`inForce`, `notInForceReason`, `endOfValidity`, `entryIntoForce`) is passed through by `lex_get_document`, `lex_get_documents_batch`, `lex_get_document_by_url`, `lex_get_metadata` and on `lex_semantic_legislation` hits. The fields are absent when the status is unknown and on API versions that do not send them.

### Changed
- Shorter README; several tool descriptions trimmed. No tool or parameter is renamed and no tool is removed; the schema and output changes are listed below.
- Redirects answered by the API are followed only on the origin of the configured base URL, or from http to https on the same host (default ports), at most 5 in a row; the API key, or the OAuth token, and the other request headers are sent only there. A redirect to any other host is not followed and no request is made to it: the call fails with an error that names that host's origin. Before, such a redirect was followed and the `x-api-key` header was sent to its target. Method and body follow the usual rules (303, and 301/302 after a POST, continue as a GET without the body; 307/308 repeat the request).
- `lex_cited_by`, `lex_cites`, `lex_citation_network`, `lex_citation_path`, `lex_related` and `lex_counterparts` accept a national document id with letters outside ASCII (for example `AT-JUD-JJT_20200101_OGH0002_PRÄ0000_001`), and `:` or `+` in it, as `lex_check_citation` already did; every id accepted before is still accepted. On these tools and `lex_check_citation`, an id typed with combining marks (NFD, "A" followed by U+0308) is accepted and sent in its composed form (NFC).
- `lex_check_citation`: a CELEX with a variant tag (`32016R0679_SUM`, `_RES`) is read as the CELEX without the tag, which is how the API resolves it; `basis.celex` says so.
- `lex_act_history`: a CELEX with a tag such as `_SUM` or `_RES` (`32016R0679_SUM`) is read as the act without the tag, as `lex_check_citation` reads it; `basis.celex` says so, and `requested` keeps the id that was given.
- `lex_get_national_document`: an `id` typed with combining marks (NFD) is sent composed (NFC), as on the citation tools. `lex_list_national_documents`: `q` likewise. Their length limits are checked on the composed form.
- A redirect that is not followed has its own error text, without the advice to retry (the same call is answered the same way). A redirect on the API's origin whose target carries a user name or password is refused at once (before, the call was retried and then failed as a network error). A redirect to a target that is not http or https is named by its scheme (was "(null)"). The workflow tools (`lex_check_citation`, `lex_act_history`, `lex_research`) report such a redirect as `upstream_error` with that text and start no further call.
- `tools/list` is smaller: whole-number parameters without an upper bound (`offset`, `page`, `version`, `deliveriesOffset`) no longer publish `"maximum": 9007199254740991`. They are still published as `integer` with their minimum, and accept the same values.
- Descriptions: the identifier of the citation tools and `lex_counterparts` no longer says "(with includeNational)" (a national id is accepted without it; `lex_counterparts` has no such parameter); `jurisdiction` on the national tools points at `lex_national_coverage` for the live countries.
- `lex_national_semantic_case_law` no longer copies a `hyde` field from the API response; the tool sends no `hyde`, so the API returns none.
- `lex_national_semantic_case_law` / `lex_national_semantic_legislation`: `partial: true` is described as a search that did not finish, not as a coverage gap.
- `lex_semantic_legislation`: the description, the server instructions and the README say: "For the text in force today, pass today's date (UTC) as asOf and use only hits with asOfResolved: true. Without asOf, acts no longer in force are marked inForce: false where their status is known; since-amended or repealed provisions are not marked." The `asOf` range reads "to today (UTC)".
- `asOfCaveat.note` calls the text of unresolved hits the indexed text (was "the LATEST text").
- **Output:** `lex_get_document_version` returns the date a snapshot was looked up for as `snapshotDate` (was `asOf`); it is not an in-force date. `lex_export` results on credit plans carry a `billing` line.
- **Stricter input:** `lex_semantic_case_law.filters` accepts only the keys of the API reference (`court`, `date_from`, `date_to`, `case_number`, `ecli`, `language`); any other key is a validation error, so a misspelt `dateFrom` is refused instead of ignored. `lex_semantic_legislation.filters` accepts `language` only, the one key the legislation index reads. `lex_update_webhook.searchCriteria` has the same fields as `lex_create_webhook`, and its values are now type-checked as on create.
- Webhook `searchCriteria` (create and update) accept what the API accepts: any 4-digit `year`, as a number or a string, `domain` in any case, and `null` for any field.
- `lex_national_semantic_case_law` no longer lists `hyde`, which never had an effect there; a call that still sends it works as before.
- `lex_national_semantic_legislation` says what a hit carries instead of "current text only": `in_force`, with `valid_from` / `valid_to` where the index has them.
- `lex_semantic_legislation` says that only an `article_ref` of the form `art_N` is an `articleId`; any other form (`anx_N` annex, `rct_a-b` recitals, `par_N` / `j_N` text windows) is read with `include`.
- `language` on the national tools is described as the country's own language (any other value is an error); `lex_get_national_document.language` no longer says "default en".
- `domain` / `subdomain` on `lex_search`, `lex_recent_documents` and `lex_export` say that `NATIONAL_LAW` and the `national-*` values are EUR-Lex's own collections and that member-state law is in the `lex_national_*` tools.
- `lex_update_webhook`: `watchCelex` and `searchCriteria` each say that they replace what is stored.
- The page, batch and webhook limits are no longer listed per tool; `lex_info` returns the caller's (`maxPages`, `maxBatchSize`, `maxWebhooks`). The semantic result caps stay on the `limit` parameters. What holds for every national tool (live countries, the monthly allowance, `includeNational`, and BUSINESS+ meaning BUSINESS, SCALE and ENTERPRISE) is said once, in the server instructions; the tools that return `attribution` still say it must be kept with republished content.
- `lex_counterparts`, `lex_transposition`, `lex_get_national_document` and `lex_export` state their cost only; what is reserved or refunded is said in the error text (402 on `lex_export` and `lex_get_national_document`: what is reserved; 403: no credits charged; 404: at most 1 credit) and, on credit plans, in the `lex_export` result.
- Every parameter has a description; the fields inside `lex_update_webhook.searchCriteria` are described once, on `lex_create_webhook`, and the parameter points there. Date and CELEX formats are stated in the descriptions and checked as before; they are no longer repeated as regular expressions in the schema.
- With `LEXAPI_MCP_READ_ONLY`, the remaining descriptions do not name the hidden tools.
- A test compares the credit costs in the descriptions, the 402 texts, the `lex_export` billing line and the README credits column with the API's operation weights (`tests/fixtures/operation-weights.json`, refreshed with `scripts/refresh-operation-weights.mjs`).
- Errors: a `403 PAYMENT_PAST_DUE` (a subscription payment failed and was not completed in time, so the API refuses requests until it succeeds) has its own text. It says that the payment failed, that access returns when the open invoice is paid or the card is updated in the dashboard, that the call is not retryable until then and that no credits were charged. The API's `billingUrl` is shown when it is an https URL on the host of the configured API base URL, and `accessEndedAt` when it is a valid UTC timestamp. Before, it read as a plan refusal with a pointer to the pricing page. `lex_check_citation`, `lex_act_history` and `lex_research` report it as `payment_past_due` and start no further call. Other `403` texts are unchanged.
- The `404` for a route the API does not have is recognised by `error.details.reason: "unknown_endpoint"` (LexAPI API 2.27.0) when the API sends it, and by its message on older versions. Other `404` texts are unchanged.

## 0.5.0 — 2026-11-16

Brings the citation-graph tools in line with LexAPI API 2.11.0 (transposition, counterparts, edge provenance and filters); **requires LexAPI API 2.11.0**. The coverage fields of API 2.12.0 / 2.13.0 are passed through unchanged.

### Added
- **`lex_transposition`** (5 credits, every plan): the measures the member states (and the United Kingdom) notified to the Commission for an EU act, grouped by country, from the Publications Office's Cellar records. The API's `note` — a notification is not a finding that the measure transposes the act, or transposes it completely — is always kept, and the tool description tells the model to say so. On BUSINESS, SCALE and ENTERPRISE, for live countries, the measures LexAPI holds carry `id` / `resolved` / `resolution` / `resolutionBasis`, and measures recorded by the national source itself are added (`provenance: "source"`); `termsRequired` is surfaced. `jurisdictions` and `resolvedOnly` are forwarded; the measures are bounded by `limit` (default 50, at most 200) / `offset` across countries and about 40,000 characters per result, with every country's `counts` and `source.cellar.attribution` kept; when the API truncated its answer, the result says so and where the full numbers are.
- **`lex_counterparts`** (20 credits, BUSINESS, SCALE and ENTERPRISE only): a national document's counterparts in the other live countries, through the EU acts it transposes or implements, ranked 1–3; an EU act as `id` lists its measures the same way. `jurisdictions` is forwarded; output is bounded to 25 EU acts and about 40,000 characters per call (`offset`) and `limit` counterparts per act (default 10, at most 50).
- **Edge filters** on `lex_cited_by`, `lex_cites`, `lex_citation_network`, `lex_citation_path` and `lex_related`: `citationType` now takes a list (and the new type `transposition`), plus `provenance`, `resolution` and `jurisdictions`. Lists are sent comma-separated; values are validated before the call.
- `language` (the language of the titles shown) on `lex_cited_by`, `lex_cites`, `lex_citation_network`, `lex_citation_path`, `lex_related`, `lex_transposition` and `lex_counterparts`.
- **`unresolved`** on `lex_cites` and `lex_citation_network` (national document ids): the references that could not be turned into an edge, the first 100 shown, with `unresolvedTruncated`.
- Citation results show each edge group's `provenance` and `resolution`, and a node's `jurisdiction` (national documents only) and `documentKind`; `lex_cited_by` / `lex_cites` keep `totalEdges` and `countsSource` (API 2.10.0), `lex_citation_network` keeps `paging.countsSource`. `lex_citation_stats` passes `byJurisdiction`, `byProvenance` and `transposition` through.
- `describeError`: a legacy-shape `400 INVALID_PARAMS` now shows `param` and `allowed`; `403 NATIONAL_TERMS_NOT_ACCEPTED` points at the one-time acceptance in the dashboard (`acceptUrl`); a `503 TIMEOUT` (counterparts) says it was refunded and to narrow with `jurisdictions`.
- `lex_national_semantic_case_law` / `lex_national_semantic_legislation` keep `partial` / `partialReason` (`SEARCH_INCOMPLETE`): the national index could not complete the search, so results may be incomplete; both descriptions say so.
- `describeError`: `422 NATIONAL_SEMANTIC_FILTER_UNREACHABLE` says the index cannot search that slice completely, that it is not a "no matches" answer, and to rephrase the query or change the filters (not retryable as is); a `503 NATIONAL_SEMANTIC_UNAVAILABLE` with `partialReason: "SEARCH_INCOMPLETE"` says it is not a "no matches" answer and gives the wait, or — without one — to try later or rephrase.
- `lex_resolve`'s description explains `resolvedVia` (incl. `eli-cellar`) and `verified` (passed through when the API sends them); it suggests checking the CELEX only for an unverified `eli` answer.

### Changed
- A `503` whose body says `TIMEOUT` (a server-side time budget ran out) is no longer retried automatically; other 503s are retried as before.
- A `503` with `partialReason: "SEARCH_INCOMPLETE"` is retried at most once, only after its wait (`Retry-After`, else the body's `retryAfter`; at most 10 s) and only when at least 15 s of the call's deadline is left after it; without a wait it is not retried. Other 503s are retried as before, and a 503 is never described as a rate limit.
- `lex_national_coverage`'s description mentions the `citationGraph` measurements it returns.

## 0.4.0 — not published (included in 0.5.0)

Adds national-law support (member-state legislation and case law alongside EUR-Lex; **requires LexAPI API 2.8.0**) and **Sign in with LexAPI** on the hosted server.

### National document shape (API 2.8.0)
- The national tools present the same fields for every country, read from the normalized contract and never from a source's raw keys (Austria's `gericht`, Germany's `aktenzeichen`, the Netherlands' `zaaknummer`, …): `documentKind` (`act` | `decision`) on listing rows, documents and semantic hits; on a decision, `lex_get_national_document` flattens `decision` into `court`, `chamber`, `caseNumbers` and `citedNorms` (`{ text, documentId }`) — also when the decision has no text; articles are `{ number, title, section, text, inForceFrom, inForceTo }` (a unit without text keeps `text: null`). The text's language facts (`textLanguages` when it differs from the document's language, `textLanguage`, `embeddedForeignText`) and a confirmed `repeal` are surfaced at the top level. Null-filled summary fields are compacted away, as before.
- `lex_national_semantic_case_law` hits take `documentKind`, `title`, `ecli` and `dateOfDocument` from each hit's `document` (LexAPI's own record), falling back to the index's metadata; `court` and `caseNumbers` come from the index. `lex_national_semantic_legislation` hits add `documentKind`, `documentType`, `valid_from` and `law_type`.

### Added
- **5 tools**: `lex_national_coverage` (which countries are live, and their legislation/case-law/semantic coverage, sources, licences and attribution — call this first), `lex_list_national_documents` (browse by title/type), `lex_get_national_document` (fetch one by id), `lex_national_semantic_case_law` and `lex_national_semantic_legislation` (separate tools, mirroring the `lex_semantic_case_law` / `lex_semantic_legislation` split — different filters and billing notes). Every tool but the coverage one states in its description that a country may be registered but not yet available to customers, and to call `lex_national_coverage` first.
- **National-law allowance**: `X-National-Limit` / `X-National-Remaining` / `X-National-Reset` response headers are surfaced as `allowance: { limit, remaining, resetsAt }` on every national tool's result (omitted for BUSINESS and higher, which have no separate limit). A `402 NATIONAL_ALLOWANCE_EXHAUSTED` gets its own actionable message in `describeError`, distinct from the credit-pool `CREDITS_EXHAUSTED` message: it's a separate monthly counter, a credit top-up does not help, and it resets at the start of next UTC month.
- `attribution` (the official source and its licence, e.g. RIS, gesetze-im-internet.de, Normattiva, Légifrance/Judilibre, the Rechtspraak open data) is kept on every national document and every semantic hit — never dropped by response shaping, since it's required legal attribution, not optional context.
- National legislation search has no `asOf` parameter (not supported for national law); national case-law search accepts `hyde` for schema compatibility with `lex_semantic_case_law` but it is always a no-op (the national index never rewrites, so it never costs the 15-credit premium).
- **`includeNational` on the citation-graph tools** (`lex_cited_by`, `lex_cites`, `lex_citation_network`, `lex_citation_path`, `lex_related`, `lex_citation_stats`): also returns/follows national neighbours of live countries (BUSINESS, SCALE and ENTERPRISE only — 403 below that). `celexNumber` and `lex_citation_path`'s `from`/`to` now also accept a national document id directly (e.g. `"AT-NOR-12345"`); `includeNational` is carried through response shaping. `lex_extract_citations` is unchanged (CELEX/EU-only).
- A national document its source withdrew (a takedown, a pseudonymisation fix) now answers `410 DOCUMENT_WITHDRAWN` — a dedicated `describeError` branch says it's gone for good (not retryable), to drop any cached copy, and not to try to identify who it was about. Covers both envelope shapes: the typed one (`lex_get_national_document`) and the legacy one (citation tools for a withdrawn national id). `lex_list_national_documents` gained `cursor` (pages past the first 1,000 rows that `page` reaches) and the response fields `totalExact`/`hasMore`/`nextCursor`; `q`'s minimum length is 3; its cost stays 3 credits flat.
- A licensing/permitted-use guardrail in `SERVER_INSTRUCTIONS`: consolidated national texts are not authentic; never re-identify anonymised/pseudonymised parties; never evaluate/compare/predict individual French judges (art. 33 loi n° 2019-222).
- **Sign in with LexAPI** on the hosted server (`https://mcp.lex-api.com/v1`). MCP clients that support MCP authorization (OAuth 2.1) can connect with your LexAPI account instead of a pasted API key: add the URL, sign in, approve the consent page. Calls are billed to your plan exactly as with an API key, and you can disconnect the app at any time from the LexAPI dashboard.
- OAuth Protected Resource Metadata (RFC 9728) at `https://mcp.lex-api.com/.well-known/oauth-protected-resource/v1`. An unauthenticated request gets `401` with `WWW-Authenticate: Bearer realm="lexapi", resource_metadata="…", scope="lex"`; a rejected or expired token gets `error="invalid_token"`, so clients refresh or re-authorize.
- A connection that is revoked while in use is answered with `401 invalid_token` where possible, or with a tool error asking to reconnect.
- `/health` reports whether sign-in is enabled.
### Changed
- `409 NATIONAL_SEMANTIC_NOT_ENABLED` and `503 NATIONAL_SEMANTIC_UNAVAILABLE` get their own `describeError` messages (point at the right country/tools, not the account); the 404 branch detects a national miss and stops pointing at `lex_resolve`/`lex_search`. `lex_national_semantic_legislation`'s `query` has a minimum length of 3 characters, matching case law. Both national semantic tools' `language` accepts the 24 official EU language codes rather than the 10 languages of the EU semantic index (a national index holds one language, and not all are in that list). `lex_get_national_document`'s cost note is "5 reserved, settles at 1" (a pool under 5 credits still 402s). `lex_list_national_documents`' `documentType` accepts up to 200 characters.
- `lex_get_national_document`'s outline reading hint points at `view "full"` + `offset` (that tool has no `articleId`/`include` parameter).
- README: how to connect from claude.ai / Claude Desktop (custom connector), Claude Code (`claude mcp add --transport http lexapi https://mcp.lex-api.com/v1`, then `/mcp` → *Authenticate*) and other MCP clients; the API-key option remains documented. The FREE-plan note now points to the pricing page instead of quoting an allowance.
- `server.json`: the remote's `Authorization` header is now optional (sign-in is discovered from the server's 401); version 0.4.0.
- Hosted server: a credential that cannot be a LexAPI API key (contains a `.` or is over 8192 characters) is answered `401` by the MCP server instead of being forwarded. No valid API key is affected.
- API keys (`Authorization: Bearer lex_…` or `x-api-key`) keep working on the hosted server exactly as before; when both headers are sent with sign-in enabled, `x-api-key` takes precedence.

## 0.3.0 — 2026-10-26

Brings the server in line with the current LexAPI API (API changelog up to the consolidated-text / `asOf` release).

### Added
- **`asOf` on `lex_semantic_legislation`** — the law as in force on a date. Hits carry `asOf`, `asOfResolved`, `asOfReason`, `asOfVersion`, `matchedVersion`; the response carries `asOf` / `asOfSummary`, plus an `asOfCaveat` when some hits could not be resolved to that date.
- **Consolidated-text labels** surfaced on legislation hits (`consolidated`, `consolidatedAsOf`, `baseCelex`, `consolidatedNote`, `baseAct`) and derived on documents fetched by a consolidated CELEX, with a `citing` note telling the model to cite the authentic act.
- 16 tools for endpoints the server did not cover: `lex_info`, `lex_resolve`, `lex_get_documents_batch`, `lex_document_versions`, `lex_get_document_version`, `lex_citation_path`, `lex_related`, `lex_citation_stats`, `lex_extract_citations`, `lex_export`, `lex_list_webhooks`, `lex_get_webhook`, `lex_create_webhook`, `lex_update_webhook`, `lex_delete_webhook`, `lex_test_webhook`.
- `lex_export` (API 2.3.0): `dateFrom` / `dateTo` (the API's document-date filter now works), `changedSince` (rows whose text changed) and `documentTypeCode` (type families); `documentType` is described as an exact, case-insensitive label match; `fetchedSince` / `changedSince` take a date or a date-time with a timezone, validated exactly as the API does (zone `Z`, `±HH:MM` or `±HHMM`; optional seconds; a 1–9 digit fraction; calendar-valid dates, also for `dateFrom` / `dateTo`). The result carries `truncatedBy` (`limit`, `max_rows` or `credits`) next to `truncated`. The cost is stated exactly: 1 credit per row returned, at least 1 per call — a 1-credit admission, a reservation up to `limit`, a refund of unreturned rows, and a 402 before anything is returned when the pool cannot cover the reservation.
- Webhook URLs are checked before the call: https, port 443/8443, no credentials, no single-label / internal / reserved hostnames, no private, loopback, link-local or other special-purpose IP literals (IPv4-mapped and NAT64 included) — the DNS-free half of the API's egress guard; the API remains authoritative.
- Missing parameters: `lex_get_document` `language`, `acceptLanguages`, `articleId`, `include`; `lex_get_document_by_url` `articleId`, `include`, `bypassCorpus`; `lex_get_metadata` `bypassCorpus`; `lex_search` `month`, `procedure`, `domain`, `subdomain`, `fresh`; `lex_recent_documents` `domain`, `subdomain`; `lex_citation_network` `citationType`, `limit`, `offset`; semantic tools `language`, `include`; `lex_semantic_case_law` `hyde` and typed `filters` (`court`, `date_from`, `date_to`, `case_number`, `ecli`).
- Server `instructions` (workflow, citing consolidated texts, `asOf` vs. version snapshots, credit awareness), tool `title`s, server `title` / `websiteUrl`.
- `LEXAPI_MCP_READ_ONLY` hides the webhook-changing tools; `LEXAPI_TIMEOUT_MS`.
- Hosted HTTP server also accepts `x-api-key`; answers `405` to GET/DELETE (stateless), `413` to oversized bodies (and closes the connection), `WWW-Authenticate` on `401`; validates `Origin` (MCP spec, DNS-rebinding defence): browser origins must be listed in `LEXAPI_MCP_ALLOWED_ORIGINS`, requests without `Origin` are allowed.
- Cancellation: an MCP `notifications/cancelled` (or a closed HTTP connection) aborts the upstream LexAPI request. Progress notifications every 10 s when the request carries a progress token (they do not raise the timeout: a server cannot tell whether the client resets its timeout on progress).
- `asOfCaveat` groups unresolved hits by reason: `notInForce` (that is the answer), `retryable`, `needsCredits`, `unavailable`, each with guidance.
- Long items (a giant annex, a `fullText` without blank lines) are split into parts that `offset` pages through; the outline's article list is bounded by `maxChars` and paged with `offset`; the outline hint only suggests parts the document has.
- Tests (vitest: unit, in-memory MCP, Streamable HTTP and stdio end-to-end against a mock API), ESLint, CI, `scripts/smoke-stdio.mjs`.

### Changed
- **Responses are compact and bounded.** Tool output is unindented JSON without the `subscription` / `usage` envelopes, legacy duplicate fields, opaque upstream metadata or snapshot-scoped ids. `lex_get_document` (and by-URL / batch / version snapshots) return the full body only when it fits `maxChars` (default 40,000 characters) — otherwise an outline with article ids, and `articleId` / `include` / `offset` to read on. v0.2 returned the whole document (hundreds of KB for large acts), which most clients truncate.
- `textAvailability` is passed through verbatim whenever text is missing (reason, languages, consolidated pointers); language fallback (`languageRequested`, `languageFallback`) and `titleLanguage` are kept.
- **Errors are actionable**: 402 states the credits needed, available and the reset date; 429 the wait; 401/403/404/5xx what to do. Both the typed and the legacy error envelopes are parsed.
- 429s from the legacy daily quota and monthly semantic quota (no `Retry-After`) say "exhausted until `usage.resetsAt` — do not retry", instead of "wait a minute".
- A top-level string `code` on a legacy-shape error body is now the error code, ahead of the legacy `error` text. A 429 with `code: "QUOTA_EXHAUSTED"` is never retried (even with a short `Retry-After`), carries no retry-after, exposes `resetsAt` (the body's `resetsAt`, else `usage.resetsAt`) and says "exhausted until <resetsAt> — do not retry, tell the user". Servers without the `code` are still recognised by the old shape check.
- `lex_export` no longer presents a partial export as the result: a stream without its `_done` trailer, a `_done` with `complete: false`, or a line whose only key is `_error` returns an error naming the rows received; an `_error` line is never returned as a row.
- One 55 s deadline per tool call (under the 60 s default of MCP clients), shared by all attempts, backoff and 429 waits; `LEXAPI_TIMEOUT_MS` raises it.
- The API key is validated at startup (no whitespace / control characters); network errors never echo runtime text (undici can quote header values).
- Retries: a 429 is retried once only when `Retry-After` ≤ 10 s (v0.2 slept on any Retry-After, twice); 500/502/503 and network errors once; 504 never (it already spent a 90 s upstream budget); webhook create/test/delete never. Every call has one deadline (55 s default; v0.2 had no timeout).
- Inputs are validated by the MCP SDK (zod) before any API call.
- CELEX inputs accept consolidated (`02016R0679-20180524`) and corrigendum (`32013R0952R(04)`) forms, lower case and a `CELEX:` prefix — v0.2's pattern rejected the first two.
- Enums synced with the API: document type `staff-working-document` added and `opinion-act` removed (the API ignores it); citation type `corrigendum`; author `civil-service-tribunal`; semantic `language` limited to the indexed languages.
- Defaults lowered to cut credit and token use: `lex_recent_documents` `limit` 20 (was 50, i.e. 15 credits when filtered), citation `limit` 50 (was 100).
- Tool descriptions rewritten: costs per call, when to use which tool, FREE plans can use semantic search (credit plans), legislation `filters` honour only `language`.
- `@modelcontextprotocol/sdk` ^1.0.0 → ^1.32.2 (protocol 2025-11-25), high-level `McpServer` API; `zod` added; dependency overrides removed (`npm audit`: 0 vulnerabilities).
- `User-Agent: lexapi-mcp/<version>` on every request.

### Breaking
- Tool output shape changed (compact; large documents outlined). Prompts that relied on v0.2's raw API JSON (e.g. `document.content.fullText` always present) need `include: ["fullText"]`.
- Inputs are validated before any call; v0.2 forwarded anything. Newly rejected:
  - `documentType: "opinion-act"` (it never filtered anything);
  - `lex_semantic_case_law.query` shorter than 3 characters (the semantic index rejects it; the API answered 502);
  - semantic `language` outside the 10 indexed languages (`en, fr, de, es, it, sl, el, nl, pt, pl`); document/search `language` outside the 24 EU codes;
  - `lex_search.maxPages` above 100 (the highest plan cap); `year` outside 1950–2100; `month` outside 1–12;
  - malformed CELEX numbers, dates not in `YYYY-MM-DD`, unknown webhook `searchCriteria` keys.
- Smaller defaults: `lex_recent_documents` `limit` 20 (was 50), citation `limit` 50 (was 100).
- `LEXAPI_MCP_READ_ONLY` also hides `lex_extract_citations`.
- One 55 s deadline per tool call (v0.2: no timeout at all) unless `LEXAPI_TIMEOUT_MS` is set.
- Hosted HTTP: browser requests with an `Origin` not listed in `LEXAPI_MCP_ALLOWED_ORIGINS` get 403; a malformed key (whitespace inside the value) gets 401 `malformed_api_key`; an oversized body is drained (up to 16 MB / 5 s) and answered 413, then the connection closes.
- Webhook `url` values that are not public https URLs are rejected at validation.
- Tool names are unchanged.
